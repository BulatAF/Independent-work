## native - нативные технологии ##
### Инструкция по запуску: ###
1 Найти файл *index.html*  
2 Запустить файл *index.html* в браузере
### Ответы на открытые вопросы  ###
#### HTML: ####
❓ accessibility: доступность сделана с помощью добавлений семантических тегов: `<header>`, `<main>`, `<footer>`, `<form>` а также `<label>` и `id`. Все это помогает скринридерам понимать структуру страницы, что в свою очередь помогает людям с огр возможностями здоровья.

❓ Обоснование использования подхода к верстке: используется базовая блочная верстка, flex и grid для формы авторизации не нужны в данном случае, все элементы идут друг за другом.                                         
#### CSS: ####
❓ Выбор брейкпоинтов - я сделал 3 брейкпоинта: для телефонов, для пданшетов и для пк. 
Чтобы заметить их работу, нудно просто поиграть масштабом в браузере.
#### JS: ####
❓ Объяснение почему выбрал данный способ хранения данных: localStorage является наиболее подходящим решением, так как сохраняет знаечние email и пароля после закрытия страницы. sessionStorage хранит до закрытия - это не имеет смысмла с точки зрения UX. Хранение пароля в localStorage небезопастно, но для учебного проекта оно было реализовано.  

❓ Использование стрелочные и именованные функции: именованные привычнее и понятнее, они мне больше нравятся, правда прикольнее писать стрелочные. Стрелочные в написании удобнее, именованные для чтения. Лучше именованные тогда, ведь пишем мы раз, а читать потом код надо много раз, и возможно не только нам.

## infrastructure -  нативные технологии, но с инфраструктурой ##
### Инструкция по запуску: ###
1 Открыть терминал (Git Bash) и перейти в папку: `cd infrastructure`  
2 Выбрать версию Node из `.nvmrc`: `nvm use 20.18.0`  
3 Установить зависимости: `pnpm install`  
4 Запустить дев-сервер: `pnpm serve` и открыть http://localhost:5173

### Ответы на открытые вопросы  ###
#### Менеджер пакетов: ####
❓ Выбрал pnpm: он быстрее npm и занимает меньше места, потому что пакеты хранятся в одном общем хранилище.

#### Версия Node: ####
❓ Версия зафиксирована через nvm: 20.18.0 записана в `.nvmrc` и в `engines.node` в `package.json`. Выбрана 20.18.0, потому что она стоит у меня, а новее установить не удалось (nodejs.org сайт не загружается вообще). Из-за этого выбраны старые версии пакетов под эту Node: ESLint 9, Vite 6, jsdom 26.

#### TypeScript: ####
❓ В `tsconfig.json` включён режим `strict` и несколько дополнительных проверок: ругается на неиспользуемые переменные и параметры (`noUnusedLocals`, `noUnusedParameters`), на функции, которые не везде возвращают значение (`noImplicitReturns`), и на элементы массива, которых может не быть (`noUncheckedIndexedAccess`). Так ошибки видны до запуска. `tsc` только проверяет типы (`noEmit`), а сайт собирает Vite. Тип данных приложения: интерфейс `Credentials` (e-mail и пароль) в `src/index.ts`. Элементам страницы указаны точные типы (`HTMLInputElement`, `HTMLAudioElement` и тд.).

#### Сборщик: ####
❓ Выбрал Vite. TypeScript и CSS поддерживаются без настройки, готовая сборка идёт через Rollup. Vitest использует тот же конфиг, что и Vite.

#### Линтер: ####
❓ ESLint с готовыми строгими правилами для TypeScript. Он проверяет код и находит ошибки, которые сам TypeScript не видит. Одно правило я отключил, потому что оно спорило с другим правилом из этого же набора. Конфигурацию airbnb не взял: она не работает с новым ESLint.

#### Форматтер: ####
❓ Prettier автоматизирует расстановку кавычек и отступов. Настройки в `.prettierrc`: точки с запятой, одинарные кавычки, отступ 2. Не форматируются `dist`, `node_modules` и `pnpm-lock.yaml` (`.prettierignore`).

#### Тесты: ####
❓ Vitest + jsdom. Vitest сам понимает TypeScript, поэтому дополнительные пакеты не нужны. `jsdom` - это «браузер внутри компьютера» без окна, он нужен, чтобы тест мог работать со страницей. Тест создаёт страницу с формой, вводит e-mail и пароль, нажимает кнопку и проверяет надпись.

## framework - разработка с фреймворком ##
### Инструкция по запуску: ###
1 Открыть терминал (Git Bash) и перейти в папку: `cd framework/my-app`  
2 Выбрать версию Node из `.nvmrc`: `nvm use`  
3 Установить зависимости: `pnpm install`  
4 Запустить дев-сервер: `pnpm run dev` и открыть http://localhost:5173

### Ответы на открытые вопросы  ###
#### React и инфраструктура: ####
 - Использовал готовый шаблон Vite для React и TypeScript. Его сделали авторы Vite, в нём уже настроены React 19, строгий TypeScript и ESLint с правилами для React, поэтому не нужно париться с этим. Next.js не взял: это большой фреймворк с серверной частью, для одной страницы с формой он лишний. Create React App не взял: он давно не развивается. Vite я уже использовал в прошлой части, команды те же.

#### Стейт-менеджер: ####
 - Выбрал Zustand. Форма входа и прикол с гифкой и звуком - это разные компоненты, но прикол  должен знать, что пользователь успешно вошёл. Поэтому данные (e-mail, пароль, надпись статуса, вошёл ли пользователь) вынесены в хранилище `src/store/authStore.ts`. Можно было обойтись `useState` и передавать данные через props, но тогда логика осталась бы внутри компонентов и `App` стал бы засорен этой логикой. Redux Toolkit не взял, слишком много лишнего кода. React Context не взял, требует обёртку-провайдер. Zustand создаётся несколькими строками, провайдер не нужен, у него есть типы TypeScript.
